## 3. What I observed
- In older Waterfall setups, testing was an isolated gate at the end, whereas in modern Agile/DevOps, quality checks run continuously across every stage.
- In Windows, when a command is typed without a path, the OS searches folders listed in PATH from left to right; if missing, it returns 'not recognized'.
- Local git commits remain strictly on the local machine; work not pushed to the remote repository does not count because it cannot be reviewed or tested in CI pipelines.

## 4. What I learned
- Why performance testing is needed: a feature can pass all functional tests for 1 user but take 20 seconds when 500 users log in concurrently due to server resource exhaustion.
- The distinction between Quality Assurance (preventive, process-focused) and Testing / Quality Control (corrective, product-focused).
- How output redirection (`dir > files.txt 2>&1`) combines stdout and stderr into a single log file.
